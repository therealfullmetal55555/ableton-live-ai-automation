# Ableton Arrangement Generator — руководство

## Что делает проект

Проект генерирует MIDI-аранжировку на 80 тактов и отправляет её
в Ableton Live через существующий JSON/TCP-мост на localhost:9877.

Генерация и отправка в Ableton разделены:

1. Сначала создаётся `arrangement_plan.json`.
2. План проверяется.
3. Только после явного подтверждения данные отправляются в Live.

По умолчанию Ableton не изменяется.

## Что проект НЕ делает

- Не является нейросетевым композитором.
- Не выбирает автоматически инструменты и сэмплы.
- Не выполняет мастеринг.
- Не анализирует аудиореференсы.
- Не гарантирует готовый коммерческий релиз.
- Не создаёт настоящий pitch slide: для него нужны настройки
  конкретного басового инструмента или отдельная автоматизация.

## Требования

- Python 3.10+.
- Ableton Live с работающим мостом, совместимым с командами
  исходного проекта.
- Пустой проект-шаблон Ableton с MIDI-дорожками по индексам:

| Индекс | Роль | Требование |
|---:|---|---|
| 2 | Bass | Басовый инструмент |
| 3 | Kick | Бочка на MIDI-ноте 36 |
| 4 | Snare | Снейр на MIDI-ноте 38 |
| 5 | Hats | Закрытый хэт на MIDI-ноте 42 |
| 6 | Lead | Лид-инструмент |
| 7 | Chords | Инструмент для аккордов |

Индексы начинаются с нуля. Названия дорожек сами по себе не важны,
важно их положение и установленные инструменты.

## Первичная проверка

```bash
python ableton_ai_automation.py --self-test
```

Ожидаемый результат:

```text
Self-test passed.
```

## Создание плана без Ableton

```bash
python ableton_ai_automation.py
```

Создаст `arrangement_plan.json`. К Ableton подключаться не будет.

Чтобы получить другую небольшую вариацию хэтов:

```bash
python ableton_ai_automation.py --seed 123
```

Одинаковый seed даёт одинаковый план.

## Отправка в Ableton

1. Сохранить текущий проект Ableton.
2. Открыть отдельную копию или пустой шаблон.
3. Проверить, что дорожки 2–7 существуют и не содержат arrangement-клипов.
4. Проверить, что мост работает на localhost:9877.
5. Выполнить:

```bash
python ableton_ai_automation.py --apply --confirm-template
```

Скрипт не удаляет клипы. Если на целевых дорожках уже есть
arrangement-клипы, он остановится.

Если связь с мостом оборвётся в процессе, часть клипов может
остаться созданной. Автоматического отката нет. В таком случае
не запускай команду повторно поверх того же проекта: открой
чистую копию шаблона.

## Музыкальная логика

- Темп: 150 BPM.
- Размер предполагается 4/4.
- Гармония: Am — F — C — G.
- Бас следует корням аккордов.
- Лид использует ноты текущего аккорда.
- Verse, Drop и Climax имеют разную плотность партий.
- Заметные снейр-филлы ставятся на концах секций, а не каждые четыре такта.
- Вступление, брейк и аутро оставляют больше пространства.

Это начальная композиционная модель, а не универсальный
генератор любых музыкальных жанров.

## Почему результат всё ещё может звучать плохо

MIDI — только часть музыки. Качество также зависит от:

- Инструментов на дорожках.
- Подходящих сэмплов ударных.
- Регистра и характера басового инструмента.
- Баланса громкостей.
- Эквализации и обработки.
- Ручного отбора удачных музыкальных идей.

Не добавляй прежний sample_loop.wav поверх всей композиции
без проверки его тональности и содержания: он может конфликтовать
с аккордами и басом.

## Рекомендуемый порядок доводки звучания

1. Отключить все эффекты.
2. Выбрать подходящие kick, snare и hats.
3. Выбрать бас, который уверенно воспроизводит низкие ноты.
4. Добиться, чтобы Verse и Drop отличались на слух.
5. Настроить громкости без перегрузки мастера.
6. Только после этого добавлять Saturator, Drum Buss, фильтры и автоматизацию.
7. Сделать рендер 16–32 тактов и оценить его на слух.

## Известные ограничения

- Протокол TCP-моста взят из исходного скрипта проекта. Его фактическое поведение нужно проверить на установленном мосте.
- В этом проекте нет автоматически создаваемых инструментов.
- Формат ответа и названия команд могут отличаться в другой версии моста.
- Скрипт не проверяет на слух получившийся трек.
- Функция `set_arrangement_clip_property` должна поддерживаться мостом.
- Если мост сообщает об ошибке не через `success: false` или `error`, обработку ответа потребуется адаптировать.

## Следующий этап развития

После того как базовая версия стабильно работает:

1. Записывать короткий рендер из Ableton.
2. Оценивать его по конкретным критериям: грув, мелодия, плотность, развитие, конфликт баса и бочки.
3. Перегенерировать только проблемную партию.
4. Хранить несколько кандидатов и выбирать лучший на слух.
5. Добавить конфигурации жанров и подбор звуков.
6. Лишь затем подключать LLM для генерации планов и объяснения правок.

Управление Ableton и музыкальное качество — разные задачи.
Рабочий TCP-мост не равен хорошему композитору.
